agentlog - Claude Code and Codex session logs: what agents keep getting wrong, and what was said

Usage:
  agentlog repeats [--tool T] [--top 30] [--all] [-v | --examples N]
  agentlog tool NAME [--uses RE] [--fail RE] [--alt RE] [--alt-tool T,T]
                     [--escape RE] [--escape-tool T,T] [--ignore RE] [-v]
  agentlog daily NAME=REGEX... [--in input|result|any] [--tool T] [--failed]
  agentlog search REGEX [-i] [--who user|assistant|any] [--limit 50] [--source S]
  agentlog show SESSION [--grep RE | --at TIME] [--around 5] [--full] [-i] [--source S]
Every command takes:
  --since WHEN  --until WHEN  --project S  --exclude S  --json
  --root DIR (Claude Code's logs, default ~/.claude/projects)
  --include-self (run inside Claude Code, the running session is left out by default)
  --since defaults to 14d, but to no limit for search and show (look back as far as needed).
  WHEN is 2026-10-07, 2026-10-07T08:57 (local), 2026-10-06T23:57Z, or 14d / 6h ago.
search and show also read Codex's logs: --source claude|codex|all (default all) and
  --codex-root DIR (repeat it; default ~/.codex/sessions and ~/.codex/archived_sessions).

Examples:
  agentlog repeats --since 2026-10-01               same failure in two or more places
  agentlog repeats --tool Bash -v                   with the commands (may hold secrets)
  agentlog tool rpatch --since 2026-10-06T23:57Z    did it fix itself, or go another way?
  agentlog tool devsrv --since 2026-10-01           other ways per day, before and after
  agentlog daily wt='isolated in the worktree' poll='until .*sleep' --since 2026-10-01
  agentlog search 'too loose' -i --who user         what was said, oldest first
  agentlog search 'Planconfig' --source codex       only Codex's logs
  agentlog show 1a2b3c4d --at '2026-10-02 14:25'    read around a hit (id and time as printed)

Output: text tables; --json prints one JSON object instead (search: one object per hit,
one per line). Commands appear only with -v/--examples, since they can hold credentials;
show prints each tool call as a one-line note and never the result.
Exit status: 0 ok (also with 0 hits); 2 invalid input, or SESSION not found or not unique;
3 the log directory cannot be read.

search: one line per utterance that matches (the first match in it): local time, who
  (user, assistant, or task = a prompt the parent gave a subagent), source (claude or
  codex), id, project, and about 40 characters either side. Oldest first; past --limit
  the newest are kept and the count is printed. Only typed words and the assistant's text
  are searched: not tool inputs, tool results, thinking, system reminders or other text
  the harness adds. id is 8 characters of the session, or SESSION/AGENT for a Claude
  subagent. Project is the session's first working directory, without home and
  project/prod/. -i ignores case.
show: SESSION is an id or its first characters (several fit: they are listed, exit 2).
  It prints the utterances in order, tool calls as `[Bash] first line…`. --grep RE (first
  utterance that matches) or --at TIME (nearest; to the minute covers the minute) picks
  one, and --around N shows N utterances either side; neither: the whole session.
  Utterances are cut at 2000 characters unless --full.

Codex logs (search and show; repeats, tool and daily read Claude Code's logs only):
  A Codex id is the LAST 8 characters of the session: ids start with a time, so sessions
  of one period share their first characters. show takes any part of an id (several fit:
  they are listed, exit 2). Roots: every --codex-root DIR, else those of ~/.codex/sessions
  and ~/.codex/archived_sessions that exist. For a copy kept elsewhere give both of its
  directories, e.g. --codex-root ~/.local/share/agent-log-archive/codex/sessions
  --codex-root ~/.local/share/agent-log-archive/codex/archived_sessions. One session
  found in several places is read once, from the largest file (the first if equal).
  Not the user's words in a Codex log: what the app adds to a user message (browser and
  environment context, AGENTS.md, plugin lists, attachment lists, image tags, interrupts,
  subagent notices). Prompts in a subagent's session are task. Reasoning is left out.
  A forked subagent's file begins with copies of its parent's lines; they are skipped.
  Lines that cannot be messages are not parsed: all 26 GB takes about 5 s.

What it counts (repeats, tool, daily):
  Each session file and each subagent file is one context (a subagent starts empty, so
  the same mistake there counts again). The window applies to each call's own time, so
  a resumed old session does not bring its old calls in.

  repeats: failed calls grouped by signature: the tool, for Bash the program, and the
  first error line with paths, ids and numbers flattened (a call refused before it ran,
  by the harness or a hook, has no program). Calls the user refused or stopped are left
  out. Sorted by rep (contexts that had it twice or more), then ctx (contexts that had
  it). streak is the longest run of it on one tool with no passing call of that tool
  between. A failure seen once is left out (--all shows it).

  tool: one failure fixed on the next call is fine. It reports runs of failures and
  what came after each run: the tool again (fixed), another way of doing the job (went
  another way), or the end of the context. Calls of neither kind between are skipped.
  Presets: rpatch (other ways: Edit, python replace, sd, sed -i, perl -i; right after a
  failure also Write, cat >, >|) and devsrv (other ways: lsof -i, pkill, nohup, kill,
  `server &`, until-curl loops). Any other NAME is a tool name (Edit, an MCP tool), or
  a Bash program with --uses; the options below replace the preset's.
  --fail RE: the tool itself failed (the result matches), not a command after it.
  --alt RE / --alt-tool: another way, counted per day and as going another way.
  --escape RE / --escape-tool: counted only as going another way right after a
  failure (Write makes new files all day; rewriting the failed file is an escape).
  --ignore RE: an --alt/--escape match that does not count (writing under /tmp).
  --since the day the tool arrived: before it, the other ways are not escapes.

  daily: calls per local day whose input (the Bash command, the file path, or the tool
  input) or result matches each REGEX.
