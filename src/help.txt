agentlog - Claude Code and Codex session logs: what agents keep getting wrong, and what was said

Usage:
  agentlog repeats [--tool T] [--top 30] [--all] [-v | --examples N]
  agentlog tool NAME [--uses RE] [--fail RE] [--alt RE] [--alt-tool T,T]
                     [--escape RE] [--escape-tool T,T] [--ignore RE] [-v]
  agentlog daily NAME=REGEX... [--in input|result|any] [--tool T] [--failed]
  agentlog search REGEX [-i] [--who user|assistant|any] [--limit 50] [--source S]
  agentlog show SESSION [--grep RE | --at TIME] [--around 5] [--full] [-i] [--source S]
  agentlog timeline --repo DIR [--who user|any] [--source S]
  agentlog memory REGEX [-i] [--type T] [--index] [--source S] [--codex-memories DIR]
  agentlog rules [--repo DIR] [--pattern RE] [--count] [--source S] [--codex-memories DIR]
  agentlog unused
Every command takes:
  --since WHEN  --until WHEN  --project S  --exclude S  --json  --root DIR (default ~/.claude/projects)
  --include-self (the running session is left out). --since defaults to 14d, none for search and
  show; memory and rules read no time window.
  WHEN: 2026-10-07, 2026-10-07T08:57 (local), …Z or +09:00, 14d / 6h ago; --until is not included.
search, show and timeline also read Codex's logs (--source claude|codex|all: show all, the others
  claude; --codex-root DIR) and cache what they read in ~/.cache/agentlog (safe to delete; --raw: no cache).

Examples:
  agentlog repeats --since 2026-10-01               same failure in two or more places
  agentlog tool rpatch --since 2026-10-01T00:00Z    did it fix itself, or go another way?
  agentlog daily wt='isolated in the worktree' poll='until .*sleep' --since 2026-10-01
  agentlog search 'too loose' -i --who user         what was said, oldest first
  agentlog show 1a2b3c4d --at '2026-10-02 14:25'    read around a hit (id and time as printed)
  agentlog timeline --repo ~/project/prod/x --since 2026-10-01   what was said and committed
  agentlog memory '関所' --type feedback            look something up in the memory files
  agentlog rules --repo . --json                    give this to a model: do any of them collide?
  agentlog unused --since 30d                       MCP, skills and CLIs installed, least used first

Output: text tables; --json prints one JSON object instead (search, timeline: one per hit; memory:
one per file; rules: one per line; each on its own line). Commands appear only with -v/--examples,
since they can hold credentials; show prints each tool call as a one-line note, never the result.
Exit status: 0 ok (also with 0 hits); 2 invalid input, SESSION not found or not unique, or --repo
not a git repository (rules: not a directory); 3 the log or memory directory cannot be read.

search: one line per utterance that matches (the first match in it): local time, who
  (user, assistant, or task = a prompt the parent gave a subagent), source (claude or
  codex), id, project, and about 40 characters either side. Oldest first; past --limit
  the newest are kept and the count is printed. Only typed words and the assistant's text
  are searched: not tool inputs, tool results, thinking, system reminders or other text
  the harness adds. id is 8 characters of the session, or SESSION/AGENT for a Claude
  subagent. Project is the session's first working directory, without home and
  project/prod/. -i ignores case.

show: SESSION is an id or its first characters (several fit: they are listed, exit 2).
  It prints the utterances in order, tool calls as `[Bash] first line…`. --grep RE (first
  utterance that matches) or --at TIME (nearest; to the minute covers the minute) picks
  one, and --around N shows N utterances either side; neither: the whole session.
  Utterances are cut at 2000 characters unless --full.

timeline: what was said and what was committed in one list, oldest first, so a review or a
  handoff reads as it happened. --repo DIR is a git repository (required). A line is the local
  time, user|commit (--who any adds assistant and task), the session id (left blank while the
  same session goes on) or the commit's short hash, and the first 100 characters; a rule line
  `--- 2026-10-02 ---` where the day changes. The id works with show. Commits: every local and
  remote branch once, merges left out, at the AUTHOR time (a rebase does not move it).
  Sessions: those whose lines were written mostly (half or more) under the repository, a
  worktree git lists, or ~/.t3/worktrees/<repo name>/ (T3 Code's, deleted ones too); lines in
  a folder above the repository (where a session was opened) count for neither side. The
  judgement uses only the lines in the window. --project S picks sessions by name instead.

memory: search the memory files, not the session logs: Claude Code's are
  ~/.claude/projects/<folder>/memory/*.md (name, description and type in a frontmatter), Codex's
  are the .md files under ~/.codex/memories/ (any form; they have no type). REGEX is looked for
  in the text, the name and the description (not in the rest of the frontmatter). -i ignores case.
  --type T (user|feedback|project|reference) keeps those; Codex's have no type, so they go.
  --source claude|codex|all (default claude), --project S / --exclude S (the project, its folder,
  or the file's path), --root DIR, --codex-memories DIR (default ~/.codex/memories).
  MEMORY.md, the index of the others, is left out unless --index. A file that several project
  folders show through a link is one hit, under the folder it really lives in (--json: also_in
  lists the others). Output: per file the project, file, type and description, then the matching
  lines as `NUMBER: text`; the count last. --json: one object per file. No window and no cache:
  --since and --until are ignored, and --raw is an error (exit 2: memory reads the memory files,
  not the logs; --raw does not apply).

rules: count the prohibitions in the memory files and list them, so that they can be read side
  by side. Whether two collide is for a person or a model to judge; nothing here guesses it.
  Default: Claude Code's memories (MEMORY.md left out, a linked file once). --repo DIR: what a
  session started in DIR reads: ~/.claude/CLAUDE.md, DIR/AGENTS.md and DIR/CLAUDE.md (a link
  to the same file counts once) and the memories of DIR's project. --source codex|all adds
  ~/.codex/AGENTS.md and Codex's memories. A prohibition is a line of text (not a heading, the
  frontmatter or a fenced code block) that matches --pattern RE; the default is loose
  (しない しません 使わない 書かない 入れない 渡さない 提案しない 禁止 やめる 避ける ならない
  してはいけ いけません 使うな, a sentence ending in ない, never, don't, do not, must not,
  avoid; case ignored), so some lines only mention one.
  Output: lines per file, most first, and the total; then every line as `file:NUMBER  [place]  text`.
  --count stops after the total. --json: one object per line (with --count, one per file and a
  last one with the totals).
  Two marks to help sort the rules by where they belong. Place: where the file lives, one of
  global (~/.claude/CLAUDE.md, ~/.codex/AGENTS.md), repo (DIR/AGENTS.md, DIR/CLAUDE.md),
  memory (a Claude Code project's memory) and codex-memory (~/.codex/memories); a column of the
  table, in the lines, and "place" in --json. also in: a Claude memory whose file name (not
  MEMORY.md) is also the name of a file in another project (a file shown through links is one
  file, so it is not another project); the table and the lines say `also in: a, b`, --json
  has "also_in" (a list, empty for none). Other projects are looked for in all of them, also
  with --repo, --project or --exclude. Whether the two copies say the same is not compared.
  A rule for one project in global, or one for every project in repo or memory, is for a
  person or a model to find; nothing here judges it.

unused: what is installed beside how often the logs used it in the window, the least used first,
  so that a review can see what could go. It only lists; whether to remove one is yours.
  Installed, from: ~/.claude.json (mcpServers, those of each project, and the claude.ai
  connectors in claudeAiMcpEverConnected), ~/.claude/settings.json (a plugin set false in
  enabledPlugins is left out), ~/.claude/plugins/installed_plugins.json (in each plugin's folder,
  the servers of .mcp.json or of mcpServers in .claude-plugin/plugin.json, and skills/),
  ~/.claude/skills/*/SKILL.md (the frontmatter's name, else the folder's), and the commands the
  "CLI tools" section of ~/.claude/CLAUDE.md names: the first word of each `code span`, but not
  in a bullet's label (before its first colon outside brackets, in its first sentence), after
  "instead of" in the same sentence, in a span that goes on a list (`, x`, `(or x)`) right after
  a span of several words (a subcommand) or an option (one of its values), or a name with no
  program on PATH (the place's line names those). Every place is printed with
  what was found there; one that cannot be read is skipped and named. Not read: a project's
  .mcp.json or .claude/skills, ~/.claude/commands, skills the app brings, Codex's settings.
  Used: an MCP server by its tool calls (mcp__SERVER__tool, SERVER with `_` for what is not a
  letter, digit, `_` or `-`; a plugin's is plugin_PLUGIN_SERVER); a skill by Skill calls and by
  /NAME typed by the user; a command by Bash calls that have it as a word (split at spaces and
  ; & | ( ) < > `, so an argument counts too, as in `brew install x`; quoted, a path, or in a
  heredoc's body it does not). Once per call. Claude Code's logs only, subagents included; the
  window applies to each call's own time.
  Output: kind (mcp, skill, cli), name, uses, last (the local day), from (where it is installed),
  the least used first. --json: one object, "read" (place and found, or error) and "items".

Codex logs (search, show and timeline; repeats, tool and daily read Claude Code's logs only):
  --source claude|codex|all: search and timeline read claude unless asked (or given --codex-root),
  show reads all. --codex-root DIR can be repeated.
  A Codex id is the LAST 8 characters of the session: ids start with a time, so sessions
  of one period share their first characters. show takes any part of an id (several fit:
  they are listed, exit 2). Roots: every --codex-root DIR, else those of ~/.codex/sessions
  and ~/.codex/archived_sessions that exist. For a copy kept elsewhere give both of its
  directories, e.g. --codex-root /path/to/copy/sessions
  --codex-root /path/to/copy/archived_sessions. One session
  found in several places is read once, from the largest file (the first if equal).
  Not the user's words in a Codex log: what the app adds to a user message (browser and
  environment context, AGENTS.md, plugin lists, attachment lists, image tags, interrupts,
  subagent notices). Prompts in a subagent's session are task. Reasoning is left out.
  A forked subagent's file begins with copies of its parent's lines; they are skipped. So
  are those a session the user forked begins with (forked_from_id without history_base):
  written as the fork is made, all stamped within seconds of its first line.
  Lines that cannot be messages are not parsed.

Cache (search, show, timeline): one file per log under ~/.cache/agentlog/<claude|codex>-<hash of
  the root>/, with the talk, a one-line note per tool call, the working directories of the
  lines, and how far the log was read. A log that grew is read from there; one that shrank or was
  replaced (another inode, or not beginning as it did) is read again whole. A last line without
  its newline is still being written: --raw and the cache both leave it for the next run. The
  caches of logs that are gone are removed. Where nothing can be written, the logs are read.
  A build that reads logs differently finds the old caches stale (the build hashes the sources
  that read them) and makes them again. Only you can read the folder (0700, files 0600).
  The window, --project, --exclude and the running-session rule apply after the cache. --raw
  reads the logs themselves (slow, certain: when the cache looks wrong).

What it counts (repeats, tool, daily):
  Each session file and each subagent file is one context (a subagent starts empty, so
  the same mistake there counts again); so is a subagent whose lines sit in its parent's
  file (isSidechain). The window applies to each call's own time, so a resumed old
  session does not bring its old calls in. A session that begins with a copy of another's
  history (the same call ids) does not count those calls again (unused neither; search
  and timeline show the copied words once). A line that is not JSON is passed over; half
  of a UTF-16 pair (an emoji cut short) reads as U+FFFD. A call the user refused or
  stopped is not a failure: not in "N failed", repeats or daily --failed, and tool
  leaves it out (it did not run). --project S keeps a session whose folder or shown name
  (its working directory, as search prints it) holds S, in these reports as in search.

  repeats: failed calls grouped by signature: the tool, for Bash the program, and the
  first error line with paths, ids and numbers flattened (a call refused before it ran,
  by the harness or a hook, has no program). Calls the user refused or stopped are left
  out. Sorted by rep (contexts that had it twice or more), then ctx (contexts that had
  it). streak is the longest run of it on one tool with no passing call of that tool
  between. A failure seen once is left out (--all shows it).

  tool: one failure fixed on the next call is fine. It reports runs of failures and
  what came after each run: the tool again (fixed), another way of doing the job (went
  another way), or the end of the context. Calls of neither kind between are skipped.
  Presets: rpatch (other ways: Edit, python replace, sd, sed -i, perl -i; right after a
  failure also Write, cat >, >|) and devsrv (other ways: lsof -i, pkill, nohup, kill,
  `server &`, until-curl loops). Any other NAME is a tool name (Edit, an MCP tool), or
  a Bash program with --uses; the options below replace the preset's.
  --fail RE: the tool itself failed (the result matches), not a command after it.
  --alt RE / --alt-tool: another way, counted per day and as going another way.
  --escape RE / --escape-tool: counted only as going another way right after a
  failure (Write makes new files all day; rewriting the failed file is an escape).
  --ignore RE: an --alt/--escape match that does not count (writing under /tmp).
  --since the day the tool arrived: before it, the other ways are not escapes.
  rpatch: an escape is another way on a file the failed call was editing (`rpatch FILE`,
  `=== FILE`, JSON "file", the file of `edits[N]`), read from the other way: Edit's and
  Write's file_path, the files of sed -i, perl -i and sd, `cat > F`, `>| F`, python's
  open(F, 'w') and Path(F).write_text. A relative path is under a leading `cd DIR`, and
  matches the end of a full path. Another way on another file is not an escape: it is
  listed as `on another file` and passed over, and what comes after it ends the run (the
  tool again: fixed; the same file: an escape). When the file of either call is not known
  (a path in a variable, an rpatch with nothing in it, `../x` with no `cd`), it counts as
  an escape as it did, apart: `went another way, file not known`. Other tools do not
  compare files.

  daily: calls per local day whose input (the Bash command, the file path, or the tool
  input) or result matches each REGEX.
